# План реализации
Цель v0.1: проверяемый трёхминутный цикл, не обещание заработка.
## M0 — переносимый репозиторий
Git, Rojo, закреплённые инструменты, AGENTS, контракт сети, план, журнал статуса, навык и инструкция передачи. Готовность: новый агент может собрать проект по README.
## M1 — игровой цикл (реализован; регрессии проверяются отдельно)
Два бесплатных Blob, merge, серверный бой 6 секунд, награда, платная покупка, минимальный UI и примитивная лаборатория. Серверные проверки, rate limit, личные снимки состояния. Release освобождает слот без компенсации после обучения, не допускает удаления последнего мутанта.
Приёмка: автоматические проверки + один игрок проходит цикл в Studio.
## M2 — сохранения и границы игроков (следующая приёмка; см. M2_ACCEPTANCE.md)
UpdateAsync с блокировкой сессии, autosave, leave/close, безопасная ошибка загрузки, отдельная тестовая среда. Приёмка: два клиента, повторный вход, ошибочная загрузка/запись и устаревшая блокировка; без потери чужого прогресса.
## M3 — проверка игрового ощущения
После приёмки M1/M2: устройство с узким экраном, понятный onboarding, улучшение анимации/звука, 5–10 наблюдаемых игровых сессий. Доработки по фактическим затруднениям. Никаких выдуманных retention-цифр.
## M4 — закрытый тест
Отдельная опубликованная тестовая experience, действующая серверная аналитика, журнал ошибок. Отслеживать завершение обучения, повторный цикл и причины выхода. Подготовить иконку/описание после проверки цикла.
## M5 — расширение и монетизация
Только по результатам тестов: расширение progression, события, косметика. Перед покупками отдельное ТЗ на ProcessReceipt, идемпотентность и восстановление. Trading/PvP/сезоны не входят в v0.1.
## Правило завершения
Код реализован, тесты прошли и Studio-приёмка выполнена — разные статусы. STATUS отражает их отдельно. Следующая задача выбирается из первого непроверенного критерия, а не из списка будущих фич.
